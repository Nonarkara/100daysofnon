# Input 28 — Prototype-First vs Plan-First: two ways to build with AI

**Source:** Thai-language infographic (source-page attribution not in the image Non sent; visual style matches the "Thai AI workflow" community pages that have produced several of today's inputs). Filed as `28-prototype-first-vs-plan-first-thai.jpg`.

**The headline question on the image:** *"สร้างโปรเจกต์ด้วย AI แบบไหนดี? คุณอยู่ฝั่งไหน?"* — *"What style of project-building with AI is good? Which side are you on?"*

The infographic splits the audience into **two styles** and lets the reader self-identify before committing to a position in the comments.

## The two approaches as the infographic frames them

### Left side — *สายต้นแบบก่อน* / Prototype-First

> Throw the big picture → Let AI make a prototype → Iterate based on user experience

Visual flow shown: quick idea (wireframe sketch) → AI builds prototype (mobile app mockup with "Discover" / "Top Picks") → usable prototype ("Hi Alex / Explore / Categories") → feedback ★★★★★ → test/fix/refine → ask *"can I add features?"*

Marketing virtue list:
- Fast, flexible, learn from real things ⚡
- See real stuff fast
- Try it and find problems
- Adjust based on real users quickly

### Right side — *สายวางแผนก่อน* / Plan-First

> Throw the big picture → Let AI plan the steps → Slowly build to completion

Visual flow shown: project overview → AI plans Roadmap (1. Analyze needs, 2. Outline, 3. Develop, 4. Test, 5. Deploy) → clear division of work (features / additions / fixes / systems / security) → architecture diagram (frontend / backend / database / docs) → divide by Phase (Phase 1, 2, 3, 4) → develop in blocks → Project Board (TO DO / IN PROGRESS / REVIEW / DONE / BURNDOWN / TEAM)

Marketing virtue list:
- Systematic, controlled direction, easy to scale 🎯
- Be systematic
- Control direction
- Scale work easily

**Bottom CTA:** *"If you had to pick only 1 way, which would you start with? Comment your reason."*

## Why this is more than a content card — it's a decision-aid framework

The infographic is set up as a binary, but the honest answer is **both work, for different contexts**. A Horizon learner needs to know *when* to reach for which. This is exactly the kind of judgment the M1 + Executive Judgment cross-cutter is built to develop.

**Reach for Prototype-First when:**
- Unclear what success looks like
- Fast iteration is available
- Low stakes / reversible
- Learning what users actually want
- Audience hasn't seen anything like this before (no useful prior to plan against)
- Solo or small team where coordination cost is low

**Reach for Plan-First when:**
- Known target / clear acceptance criteria
- Multi-team coordination required
- High stakes / irreversible decisions in scope
- Regulatory / compliance constraints
- The cost of building the wrong thing exceeds the cost of planning first
- Onboarding new team members who need a roadmap

**Common failure modes:**
- Prototype-first applied to high-stakes work → "I built the wrong thing fast"
- Plan-first applied to exploratory work → "I planned the right thing for a problem nobody had"
- Switching mid-stream without acknowledging the switch → loss of accumulated context

## Three Horizon placements

### 1. M1 lesson — "Choosing your approach: prototype-first vs plan-first"

Add to M1 as the **second sub-lesson** (after "How to be the good boss your AI deserves" from Input 16's distillation). The lesson teaches:

1. *Both approaches work.* Most AI-education content sells one as superior; Horizon teaches the choice.
2. *The choice depends on (a) reversibility of decisions in scope, (b) clarity of success criteria, (c) cost of building the wrong thing, (d) coordination cost across humans involved.*
3. *Mid-stream switches need explicit acknowledgment* or accumulated context gets lost.
4. *Default for solo / exploratory / low-stakes / mobile-first-of-mind learners: prototype-first.* Default for team / regulated / high-stakes / multi-deliverable: plan-first.
